## 一、快速开始

1. 解压/拷贝整个 `dist` 文件夹到任意目录（保留 `data\` 与 `archive\`）。
2. 双击 `BlueGuard.exe`，无黑框，自动弹出独立窗口（Edge/Chrome `--app` 模式）。
3. **打开即进入**总览仪表盘，不需要输入任何账号密码。
4. 想真拦事儿：右键 exe →「以管理员身份运行」，进入 *防护中心 → 策略* 把档位从 `观察` 切到 `阻断`。
5. 退出：关闭窗口；服务随进程结束。

> 端口：每次启动随机分配，写入 `data\port.txt`；异常日志写入 `data\launcher.log`。
> 服务化/无窗口启动：设 `BLUEGUARD_NOBROWSER=1` 再启动，自行访问 `port.txt` 里的地址。

### 恢复口令登录（多人共用一台机器时）

```bat
set BLUEGUARD_AUTH=password
BlueGuard.exe
```

初始账号 `admin` / `BlueGuard@2026`，首次登录强制改密。

## 三、功能模块详解

### 0. 防护中心（guard）— V3.0 核心

**用途**：本机主机防护引擎的操作台，采集 → 判定 → 处置 → 联动一条链路闭环。

**顶部状态条**：当前档位、引擎是否运行、事件源状态（`事件源 1s · 已捕 N`）、权限提示（未提权时明确写"只能检测与告警"）。
**工具条**：立即扫描（0.8–1 秒）/ 深度扫描（5–15 秒，刷新启动项与主机姿态）/ 启动·停止引擎 / 跳告警 / 跳事件 / 导出 CSV。

| 页签 | 内容 |
|---|---|
| 概览 | 今日事件、待研判告警、开启事件单、当前封禁 IP；严重度分布；命中 Top 规则；最近事件 |
| 事件 | 按级别/状态/类别筛选 + 关键词搜索 + 分页；每条带 ATT&CK 编号、对象、处置结果、研判与删除按钮 |
| 规则 | 69 条内置规则 + 5 条攻击链模板，显示类别/级别/ATT&CK/命中次数/动作；每条可停用启用、可"自测"（合成样本验证规则打得中） |
| 策略 | 三档档位（观察/告警/阻断）+ 4 个参数（扫描间隔 3–120 秒、动作阈值 1–200、每分钟动作上限 1–120、阻断过期 1–1440 分钟）+ 6 个自动动作开关 |
| 白名单 | process / ip / port / domain 四类；内置条目标注来源 default，不可删除 |
| 响应与对账 | 主机 `BlueGuard-*` 防火墙规则 vs 数据库记录对账、孤儿规则清理、全部清理、响应记录与回滚 |

**删事件（V3.2 补）**

事件列表每行右侧有「研判 / 删除」，详情弹窗底部也有「删除」。列表下方还有三个批量入口：**删除已关闭 / 删除误报 / 清空全部**。

删除的界线说得清楚一点：

| 删什么 | 不删什么 |
|---|---|
| 事件本身（引擎的观察结果） | `guard_responses` 处置留痕 —— 谁在什么时候封了哪个 IP |
| | 系统防火墙上已经下发的 `BlueGuard-*` 规则（要撤请去「响应与对账」回滚） |
| | 审计记录（每次删除都追加一条 `guard.event.delete` / `guard.event.purge`） |

也就是说：**列表可以清干净，但"做过什么"抹不掉**。如果某条事件上还挂着生效中的处置，删除时的提示会告诉你去「响应与对账」回滚。

接口：

```http
DELETE /api/guard/events/{id}                     单条
POST   /api/guard/events/purge  {"mode":"closed"}  已关闭
POST   /api/guard/events/purge  {"mode":"false_positive"}
POST   /api/guard/events/purge  {"mode":"listed","ids":[1,2,3]}
POST   /api/guard/events/purge  {"mode":"all"}     清空
```

**攻击链（V3.1）**

事件页的类别筛选里有一项「攻击链」。它不是单条规则命中，而是把最近 30 分钟的事件按 ATT&CK 战术分桶，判断"这台机器上是不是已经凑齐了一条完整攻击路径"。

| 链模板 | 要求同时出现的战术 | 级别 |
|---|---|---|
| `CHAIN-INTRUSION` | 执行 + 持久化（至少 3 个战术） | critical |
| `CHAIN-CRED-LATERAL` | 凭据访问 + 横向移动 | critical |
| `CHAIN-EXFIL` | 收集 + 外泄 | critical |
| `CHAIN-RECON-PRIVESC` | 发现 + 权限提升 | high |
| `CHAIN-DEFENSE-TAMPER` | 防御规避 + 执行 | high |

点开链事件，详情里的「证据」会给出按时间排序的战术序列（如 `执行 → 持久化 → 命令与控制`）和组成它的具体规则——这比一条孤立的"PowerShell 隐藏窗口"有用得多。链事件同样进告警、开事件单（critical 记 P1）、可人工处置，处置留有完整痕迹。

**事件源（V3.2）：轮询看不见的短命进程**

引擎有两个数据源，并行走：

| | 轮询快照 | 进程创建事件源 |
|---|---|---|
| 多久看一次 | 8 秒（策略里可调 3–120） | 约 1 秒 |
| 能看见什么 | 采样那一刻活着的进程 | 每一个被创建出来的进程 |
| 覆盖范围 | 进程、连接、监听、启动项、主机姿态 | 只管进程创建（带完整命令行与父进程） |
| 要不要管理员 | 不要 | 不要 |

为什么需要它：存活不到 8 秒的进程在两次采样之间就生灭完了，轮询永远看不到。编码命令、一次性下载器、`cmd /c` 横向工具、Office 拉起的短命 shell，全是这个形状。

界面上看「事件源 1s · 已捕 N」这个徽标：绿=在跑，灰=引擎停着（会自动一起停），黄=本机找不到 PowerShell（此时只剩 8 秒轮询）。

实测：一个只活 2.2 秒的 `pwsh -EncodedCommand`，轮询快照 375 个进程里没有它，事件源捕获到并判出 2 条 high。

**边界**：事件源是 WMI 的 1 秒粒度，存活不到 1 秒的进程仍可能漏；要做到 ETW 那种零漏报需要管理员权限开内核事件会话，本版本没做。

**三档是什么意思**

| 档位 | 引擎行为 | 适合谁 |
|---|---|---|
| 观察 | 只采集、只记录事件，不写告警台、不下发动作 | 刚装好、先摸底 |
| 告警 | 额外写告警台、自动开事件单、可推通知，仍不动系统 | 日常值守（推荐起步） |
| 阻断 | 在告警基础上真正下发防火墙阻断/结束进程（受全部护栏约束） | 已加白名单、误报可控 |

**处置为什么会被拒绝**（错误码写在日志与界面里，不静默失败）

| 错误码 | 含义 |
|---|---|
| `MODE_MONITOR` | 当前档位不是阻断 |
| `INTERNAL_IP` | 目标在 10/8、172.16/12、192.168/16、127/8、169.254/16、100.64/10、回环或链路本地段，一律拒绝（避免自断网） |
| `WHITELISTED` | 命中白名单 |
| `PROTECTED` / `SELF_PROTECTED` | 目标系统关键进程或本程序自身 |
| `PROTECTED_PORT` | 53/80/443 等基础端口 |
| `ELEVATION_REQUIRED` | 当前进程未提权，需以管理员身份重启 |
| `RATE_LIMITED` | 超过每分钟动作上限 |

**联动**：事件命中自动产生 `[防护]` 前缀告警、high 及以上自动开事件单（P1/P2）、封禁动作同步进封禁台账、全过程写入哈希链审计、可在报表中心导出。

**人工处置**：事件表点「研判」打开详情，底部有「阻断 xxx 入站 / 阻断该程序出站 / 阻断本机端口 N / 结束进程 pid N」按钮——不必等规则替你做决定。手动动作走同一套护栏（档位、内网地址、白名单、自保护、限速一个不少），执行完照样能在处置记录里回滚，照样进审计链。按钮只在该事件真的有对应字段时才出现（没有远端 IP 就不会给"阻断 IP"，避免点了白点）。

**实测证据**（提权环境下，`backend/_selftest_respond.py` 与端到端脚本）：

```
PASS block_ip ok        → 系统防火墙真实出现 BlueGuard-Block-198.51.100.9
PASS revert ok          → 规则从系统消失，封禁台账回到 allowed
PASS block_port ok      → BlueGuard-Port-* 创建 / 删除
PASS 拒绝结束 System / 自身 / 宿主        → PROTECTED / SELF_PROTECTED / INTERNAL_IP
PASS 触发限速            → limited=3
PASS audit verify       → (True, 19, None)
```

### 1. 总览（dashboard）
- **用途**：全局态势感知。
- **内容**：资产数、告警数、日志数、审计条数、最近告警/事件列表。
- **操作**：无输入，自动加载；点击告警可跳转告警页。

### 2. 网络配置（network）
- **用途**：网卡查看与 IP 变更（高危）。
- **查看**：自动列出所有网卡（名称/状态/MAC/IPv4/网关/DHCP）。
- **改 IP**：选择网卡 → 输入 IP/前缀/网关/DNS → 应用。非管理员返回 `ELEVATION_REQUIRED`。
- **快照/回滚**：变更前自动快照；失败自动回滚；看门狗超时自动还原。
- **注意**：仅在授权测试机操作，确保可回滚。

### 3. 告警（alerts）
- **用途**：安全告警管理。
- **扫描**：点击「扫描告警」按规则引擎生成告警。
- **筛选**：按级别/状态筛选；支持确认/处置。
- **字段**：时间、级别、来源、描述、状态。

### 4. 日志检索（logs）
- **用途**：把本机真实日志采进来并检索，是运营链路的数据入口。
- **采集 Windows 日志**（V3.1 新增，推荐先用这个）：从 System / Application 事件日志读最近 48 小时的记录。
  - 按「时间 + 正文前 160 字」去重：反复点不会灌重复，第二次点通常是「新增 0、跳过 N」；
  - 自动补 `host`（本机名），日志才能和资产台账对上；
  - 级别归一成 信息/警告/错误，时间统一成本地时区（PowerShell 的 `/Date(...)` 格式也能解析）；
  - Security 日志需要管理员权限，普通权限点它会在结果里单独报「失败：需管理员」，不影响其它日志。
- **级别筛选**：下拉选「错误 / 警告 / 信息」，可与关键词叠加（例如 `q=error` + 级别=错误）。
- **检索**：输入关键词/IP/主机 → 自动检索；长度 ≥3 走 FTS5 trigram，中文两字词自动降级 LIKE，页面会显示走了哪条通道。
- **生成演示日志**：只用于演示检索效果，正式环境不要点（会污染真实日志）。
- **接口**：`GET /api/logs/stats` 给出按级别/主机/天的分布，适合做健康检查。

### 5. 实时监控（live）
- **用途**：**只读**采集本机 TCP 连接表，筛出与外部 IP 建立的连接并聚合成事件，辅助判断"本机正在和谁通信"。
- **启动/停止**：点「启动监控」按间隔轮询本机连接表；点「停止监控」结束轮询。默认**不自动启动**（如需自启动，设环境变量 `BLUEGUARD_LIVE_AUTOSTART=1`）。
- **内容**：状态看板（运行状态、轮询间隔、事件数）、实时事件表（时间/外部 IP/本地端口/进程/级别/详情）。
- **操作**：事件行可点「溯源该 IP」跳到 IP 溯源页；「刷新」重载当前事件。
- **定位**：这是**连接表轮询**，不是网络抓包、不是 NDR/EDR、也不做实时拦截。详见「四、安全说明 → 能力边界」。

### 6. 溯源（trace）
- **用途**：IP/域名溯源分析。
- **操作**：输入 IP（如 `203.0.113.5`）→ 点击溯源 → 查看关联资产/告警/日志。
- **结果**：溯源链路、关联事件、风险评分。

### 7. 资产台账（assets）
- **用途**：资产登记与管理，是运营链路的第一环。
- **自动发现本机**（V3.1 新增，先点这个）：一次采集网卡 IP/MAC、系统版本、全部监听端口与监听进程，写入台账。
  - 幂等：重复点只更新，不会重复建资产；手工改过的负责人/重要度不会被覆盖；
  - 上一次发现过、这次没在监听的端口会被清掉，台账不会越积越多；
  - 动态端口（49152 以上且拿不到所属进程）不入账，避免刷出一屏临时端口。
  - 实测：`WORKSTATION-01 / Windows 10 / 4 个 IP / 16 个真实监听端口`，其中绑 `0.0.0.0` 的端口就是真实对外暴露面。
- **新增**：补录别的机器（名称/类型/IP/负责人/备注）。
- **列表**：支持搜索、编辑、删除。
- **详情**：点「详情」看完整信息与**监听端口表**（端口 / 协议 / 服务名 / 监听进程与绑定地址）。

### 8. 漏洞管理（vulns）
- **用途**：漏洞记录与跟踪。
- **字段**：CVE/名称/级别/影响资产/状态/修复建议。
- **操作**：新增/编辑/状态流转（未修复→修复中→已修复）。

### 9. 基线检查（baseline）
- **用途**：系统安全基线核查。
- **运行**：点击「运行基线」执行检查项。
- **结果**：通过/失败项列表，失败项附整改建议。

### 10. 事件管理（incident）
- **用途**：安全事件记录与处置。
- **字段**：事件类型/级别/时间/描述/处置人/状态。
- **流程**：新建→处置→关闭，全程留痕。

### 11. 值班管理（duty）
- **用途**：值班排班与交接。
- **功能**：排班表、交接记录、当前值班人显示。

### 12. 报表（reports）
- **用途**：统计报表生成。
- **类型**：告警统计、资产统计、日志趋势。
- **导出**：支持导出为文件。

### 13. 审计日志（audit）
- **用途**：操作审计追踪。
- **内容**：所有关键操作（登录/改 IP/删资产等）的审计记录。
- **字段**：时间/操作人/动作/对象/详情。

### 14. 通知（notify）
- **用途**：通知配置与发送。
- **配置**：通知渠道、模板、触发条件。
- **发送**：手动/自动触发通知。

### 15. 系统设置（settings）
- **用途**：平台参数配置。
- **内容**：用户管理、权限、系统参数、数据重置。

## 四、安全说明

| 项目 | 说明 |
|------|------|
| 认证 | HttpOnly Cookie（`bg_token`），前端 JS 不可读；12 小时过期 |
| 未登录访问 | `/api/dashboard`、`/api/health` 等返回 401；仅 `/api/ping` 免鉴权且只返回 `{"ok":true}` |
| SQL 注入 | 全部查询走参数化；登录探针 `admin" OR 1=1--` 被拒绝 |
| XSS（输出） | 前端所有动态字段经 `esc()` 转义后渲染 |
| XSS（入库） | 后端 `_SanitizeBodyMiddleware` 对 POST/PUT/PATCH 的 JSON 体逐字段做 HTML 实体转义，脏数据不再入库 |
| 信息面 | `/api/health` 已需登录；免鉴权端点仅 `/api/ping`，不含任何内部信息 |
| 密码存储 | PBKDF2 + 随机盐；连续失败 5 次锁定 15 分钟 |
| 审计 | 关键操作写审计表，哈希链校验完整性（`/api/audit` 可见 `ok/detail`） |
| 网络操作 | 高危，非管理员返回 `ELEVATION_REQUIRED`；变更前快照、失败自动回滚 |

### 能力边界（明确不做的事）

为避免误用，下面这些**不是**本软件的能力，也不要按这些预期去验收：

| 维度 | 本软件是 | 本软件**不是** |
|------|----------|----------------|
| 实时监控 | 定时轮询本机 TCP 连接表（`Get-NetTCPConnection`），筛外部 IP 并聚合 | ❌ 不是网络抓包（无 pcap 采集、无包重组、无协议解码） |
| 防护引擎 | 用户态定时巡检进程/连接/监听/启动项/主机姿态，规则 DSL 判定，可下发系统防火墙阻断 | ❌ 不是 EDR（无内核回调、无文件完整性监控、不拦内存注入、无驱动层） |
| 检测能力 | 基于本机可见数据 + 69 条规则匹配 + 攻击链关联 + ATT&CK 标注 | ❌ 不是 NDR / IDS / IPS（无镜像流量、无特征库升级服务） |
| 处置能力 | 观察档只记录；告警档写告警台并开单；**阻断档**在管理员权限下真正下发防火墙阻断（IP/程序出站/端口）与结束进程，全部可回滚、限速、白名单、自保护 | ❌ 不拦加密流量、不做内存级查杀、不接管 DNS、不拦内网横向（内网 IP 一律拒绝处置） |
| 日志来源 | 本机 Windows 事件日志（读取需管理员权限）+ 内置演示数据 | ❌ 不采集远端设备/Syslog/云平台日志 |
| 部署形态 | 单机便携版，数据全在本地 `data\` | ❌ 不是分布式平台、无多节点、无集中管控 |

因此它的**正确用法**是：本地授权测试机上的**主机防护 + 安全运营台** —— 检测看得见、处置留痕、动作可回滚；
但它**不是**"挂在网里就能发现攻击"的检测设备，也不是免授权的取证明工具。

## 七、帮助与常见问题

### Q1：启动后没有反应？
- 确认双击的是 `dist\BlueGuard.exe`（不是 `archive\` 下的旧版）。
- 查看 `dist\data\launcher.log` 最后 30 行，常见原因是端口冲突或旧进程未释放；用任务管理器结束所有 `BlueGuard.exe` 后重试。

### Q2：需要输入密码吗？
- V3.0 默认免登录（`BLUEGUARD_AUTH=open`），打开直接进。多人共用一台机器时设 `BLUEGUARD_AUTH=password` 恢复口令登录，初始 `admin` / `BlueGuard@2026`，首次登录强制改密；忘记口令可删除 `dist\data\blueguard.db` 后重启。

### Q2b：防护中心显示"只能检测与告警"？
- 当前进程没有提权（完整性级别非高，`whoami /groups` 里看不到 `S-1-16-12288`）。引擎照常检测与记录，但阻断/结束进程会被拒绝并留痕。
- 解决：右键 exe →「以管理员身份运行」。注意：仅账号属于管理员组不代表已提权（UAC 过滤令牌），必须以提权方式启动。
- 另外确认 *策略* 里档位是 `阻断`，缺一不可。

### Q2c：点阻断后事件还在，网络也没断？
- 看该事件的「处置」列与响应记录里的 `result`：`INTERNAL_IP` 表示目标是内网地址，按设计拒绝处置；`WHITELISTED` 表示命中白名单；`RATE_LIMITED` 表示超过每分钟动作上限。
- 防火墙规则只对本机生效，且只阻断你配置的方向（IP 入站 / 程序出站 / 端口入站）。

### Q3：某个模块显示"待接入"或"加载失败"？
- 关闭所有 BlueGuard 窗口，重新双击最新 `dist\BlueGuard.exe` 打开新窗口再试。
- 若仍失败，把模块名和错误文字发给维护者。

### Q4：实时监控没有发现外部 IP？
- 需要管理员权限运行（右键"以管理员身份运行"）。
- 检查 `dist\data\launcher.log` 中是否有 PowerShell 报错。
- 本机当前无外部 TCP 连接时，事件列表为空属正常。
- 注意边界：它只看**本机 TCP 连接表**。局域网内其他设备、UDP 流量、已经断开的历史连接都看不到（详见「四、安全说明 → 能力边界」）。

### Q5：改 IP 操作失败？
- 需管理员运行；VMware 虚拟网卡可能被宿主恢复，建议在物理网卡或非托管网卡上测试。

### Q6：通知测试发送失败？
- 405 错误通常表示目标 URL 不接受 POST（如本机根路径只支持 GET）。
- 请配置真实可接收 POST 的 Webhook 地址（企业微信/钉钉/Slack/自建服务等）。

### Q7：如何彻底退出？
- 点击右上角「退出」按钮，服务随窗口关闭。
- 如进程残留，用任务管理器强制结束 `BlueGuard.exe`。
